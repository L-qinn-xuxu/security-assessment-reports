# SQL注入漏洞复现报告
## 1. 漏洞概述
SQL注入是攻击者通过在输入框插入SQL语句，操纵后端数据库执行非预期查询，造成数据泄露、篡改等风险。本案例在本地Pikachu靶场完成，仅用于学习研究。

## 2. 环境信息
靶场：Pikachu
漏洞位置：GET型SQL注入页面
风险等级：高危

## 3. 原理简述
后端代码直接将用户输入拼接进SQL语句，没有做过滤与预编译处理。用户输入的单引号可以闭合原有SQL语句，插入恶意逻辑。

## 4. 复现步骤
1. 打开Pikachu靶场SQL注入模块（GET型）
2. 在用户名输入框输入Payload：`' or 1=1 -- `
> 注意：`--`后面要有空格
3. 提交，页面会返回数据库全部用户数据，注入成功。

## 5. 风险影响
1. 数据库敏感账号信息泄露
2. 可读取、修改数据库内数据
3. 严重情况下可获取服务器权限

## 6. 修复建议（面试高频考点）
1. 使用预编译语句（PreparedStatement），杜绝直接拼接SQL字符串
2. 对用户输入做严格输入过滤、白名单校验
3. 数据库账号最小权限原则，禁止应用使用高权限账号连接数据库
4. 部署WAF，拦截SQL注入特征请求

## 7. 总结
漏洞根源是代码直接拼接用户可控输入，没有做安全防护。在等保测评中，网页存在SQL注入属于高危漏洞，需要优先整改。
